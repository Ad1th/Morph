Why it stays unreproducible

  • Combinations. Latency alone passes. Loss alone passes. Both together fail.
  • Continuous variation. Network is not a bucket: 5 ms to 4000 ms, 0 % to 15 % loss, interacting with timeouts, retries and pools.
  • Timing. The failure vanishes when the debugger attaches.
Thesis

The hard part isn't knowing two machines differ. It's proving which difference matters.

How Morph works

Capture, reproduce, run, experiment, isolate.

I

Capture

A one-shot profiler reads the machine, or a user's crash report ships its profile with the logs.

II

Reproduce

OS-native adapters (tc/netem, cgroups, dnctl) or a root-free user-space TCP proxy with a real delay line and retransmit stalls.

III

Run

The app runs under the conditions; exit status, errors, timing, memory and provenance are recorded per trial.

IV

Experiment

Paired baseline/treatment trials per candidate condition, a 2×2 interaction design, a noise-aware boundary search.

V

Isolate

Minimal failing condition set, classification, and a replayable regression bundle plus a generated CI test.

# the whole loop from a shell
morph capture -o user.json          # on the failing machine
morph experiment -p user.json -c "python -m app"   # isolate, sequentially
morph threshold -p user.json --param network.latency_ms --method bayes
morph save --id checkout-lock-lease && morph export checkout-lock-lease   # regression + CI test
Research contribution · I

Evidence you can watch without lying to yourself.

The optional-stopping trap

A live p-value crossing 0.05 invites you to stop right there. Do that and the real false-positive rate is far above 5 %. Fixed-N tests are only honest if nobody peeks.

Morph's design

Trials run in matched pairs, cancelling host drift. Under "no difference" a discordant pair is a fair coin; against that null Morph runs Robbins' Beta-mixture likelihood ratio:

Em = 2m · B(k+1, m−k+1)

k = pairs where only the treatment failed, m = discordant pairs. Ville: PH0(E ever ≥ 1/α) ≤ α at every stopping time. Reject at E ≥ K/α for K conditions.

Research contribution · II

A failure boundary with a credible interval, not a fabricated point.

Posterior over the boundary · dose-response after 30 trials · true value 150 ms

Why plain bisection fails

Apps answer "does it fail here?" noisily. Halving on a majority vote lets one unlucky batch send the search into the wrong half for good, then reports it with 5 ms precision.

What Morph does

Horstein's probabilistic bisection: a posterior over the boundary, probed at its median, updated through a logistic response model whose floor and ceiling (how flaky the app is) are learned from the same trials. Two extra hypotheses, "never fails" and "always fails", stop it inventing a boundary.

The rest of the grammar

  • Holm–Bonferroni across candidates in batch mode; a K/α evidence budget in sequential mode. Family-wise error stays at α however many lanes you add.
  • One-sided tests for the directional question "does this make it worse", doubling power at small n; and an explicit warning when n is too small to ever reach significance.
  • ddmin over conditions (Zeller & Hildebrandt) returns the 1-minimal failing set: latency packet loss, not cpu ram locale.
  • Four verdicts, decided on risk-difference intervals: environment-caused, environment-exposed (a race the timing shift reveals), application-internal, no effect.
Design principle

Honesty is a feature, and it's enforced in code.

Fidelity per field

Every profile field is stamped by the adapter that applied it: reproduced approximated unavailable. A user-space proxy says so. An 8 GB machine never claims 16 GB.

Invalid trials are not failures

Exit code 2, a missing binary, a bad working directory: recorded as invalid, retried, and reported as a setup problem. They never enter a failure rate, so a broken command cannot produce a verdict.

Nothing runs silently elsewhere

Cloud dispatch to a Raspberry Pi or GCP worker is explicit (--cloud) and fails loudly. No silent fallback to a host that was just judged unable to reproduce the profile.

Also: seeded loss patterns and a provenance block (seed, Morph version, host fingerprint, profile hash) on every result, so any trial is re-runnable.

Production grade

Built to survive a hostile code review.

Security

  • Local-only API, explicit CORS origins, no drive-by RCE.
  • GitHub tokens never in argv, git config, or any response.
  • Path-validated ids for profiles, regressions, uploads.

Reliability

  • Proxy delivers every byte: loss is a stall, never corruption.
  • Crash-safe shaping state and morph doctor to clean it.
  • Process-group kills, bounded output capture, invalid-trial retries.

Engineering

  • 300+ tests across engine, runtime, API, CLI, TUI; CI on Linux and macOS.
  • Statistical properties tested by Monte Carlo, not asserted by hand.
  • Typed schemas, JSON round-trips, one service layer for CLI, API, TUI.
Prior art and what's new

No new statistics were invented. They were pointed at the right problem.

Standing on

  • Ramdas, Grünwald, Vovk, Shafer (2023), Game-theoretic statistics and safe anytime-valid inference.
  • Turner, Ly, Grünwald (2024), Safe tests and always-valid confidence intervals for contingency tables.
  • Horstein (1963); Waeber, Frazier, Henderson (2013), Bisection search with noisy responses; Watson & Pelli (1983), QUEST.
  • Zeller & Hildebrandt (2002), delta debugging; Holm (1979).
  • Delta debugging for flaky CPS test executions (arXiv 2607.25695): causal isolation for flaky failures, on simulator inputs.

Morph's contribution

  • The variable space is the real machine: OS, hardware, locale, network, with cross-category interactions.
  • A live console whose numbers are valid at every glance: the first environment-fault tool built on e-processes.
  • A closed loop: a customer's captured failure becomes a reproduced, isolated, minimal, replayable regression with a generated CI test.
